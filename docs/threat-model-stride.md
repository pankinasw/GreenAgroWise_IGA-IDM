# Модель угроз для системы ЦСУПД  
(Система управления правами доступа и учётными записями)  

Версия 1.0 от 05 декабря 2025 г.  

## 1. Введение  
Настоящий документ описывает модель угроз для системы СУПД, разработанной на основе open-source компонентов для управления идентичностями, ролями и доступами (IGA/IDM). Модель угроз построена по методологии STRIDE (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege), рекомендованной Microsoft для анализа рисков безопасности.  

Цель — выявить потенциальные угрозы, оценить их влияние и предложить меры минимизации. Анализ основан на архитектуре системы, описанной в документе "Архитектура системы СУПД".  

### 1.1. Область применения  
- Пользователи: >1000 сотрудников + подрядчики.  
- Компоненты: Traefik, Authentik, React Portal, Temporal.io, midPoint, PostgreSQL, MinIO.  
- Интеграции: 27 целевых систем (SCIM, REST, LDAP).  
- Стандарты: ISO 27001, GDPR, ФЗ-152, ФСТЭК.  

### 1.2. Предположения  
- Система развернута в Kubernetes/Docker с TLS 1.3 и MFA.  
- Внешний периметр защищен WAF/Firewall.  
- Угрозы от внутренних пользователей (инсайдеры) учитываются.  

## 2. Обзор архитектуры (кратко)  
Система включает:  
- Фронтенд: React PWA + Authentik (SSO/MFA).  
- Бэкенд: Temporal (workflow) + midPoint (IGA core, SoD, provisioning).  
- Хранилище: PostgreSQL + MinIO.  
- Ingress: Traefik.  
- Целевые системы: Интеграции через коннекторы.  

Потоки: Аутентификация → Запросы/Workflow → Provisioning → Аудит.  

## 3. Модель угроз по STRIDE  

Каждую категорию угроз анализируем по компонентам системы, оцениваем вероятность (Низкая/Средняя/Высокая), влияние (Низкое/Среднее/Высокое) и предлагаем минимизацию.  

### 3.1. Spoofing (Подмена идентичности)  
Угрозы, связанные с фальсификацией идентификаторов.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| Authentik       | Подмена пользователя через слабый MFA или кражу сессии (session hijacking). | Средняя    | Высокое | Обязательный MFA (TOTP/WebAuthn), короткий TTL токенов, мониторинг аномалий. |
| React Portal    | CSRF/XSS-атаки для подмены запросов от лица пользователя.             | Средняя    | Высокое | CSP, X-Frame-Options, secure cookies, OWASP ZAP тестирование. |
| midPoint        | Подмена в API (например, через поддельный OIDC-токен).                | Низкая     | Высокое | Валидация JWT, RBAC в midPoint, аудит всех API-вызовов. |
| Целевые системы | Подмена в коннекторах (например, MITM в REST/SCIM).                   | Средняя    | Высокое | TLS mutual auth, OAuth2 для интеграций, ротация ключей. |

### 3.2. Tampering (Манипуляция данными)  
Угрозы изменения данных в покое или транзите.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| PostgreSQL      | Манипуляция справочника пользователей/ролей (SQL injection).          | Низкая     | Высокое | Prepared statements, шифрование данных в покое (pgcrypto), доступ только через midPoint. |
| Temporal        | Изменение workflow (например, подмена этапов согласования).           | Средняя    | Высокое | Immutable workflows, цифровые подписи на шагах, аудит изменений. |
| midPoint        | Tampering матрицы ролей или SoD-реестра.                              | Средняя    | Высокое | Хэширование объектов, version control в репозитории midPoint. |
| Интеграции      | Перехват и изменение provisioning-команд (например, в LDAP).          | Средняя    | Высокое | Шифрование транзита (TLS), integrity checks в коннекторах. |

### 3.3. Repudiation (Отказ от действий)  
Угрозы, когда действия не могут быть доказаны.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| React Portal    | Пользователь отрицает подачу заявки.                                  | Низкая     | Среднее | Полный аудит действий (логи с timestamps и IP), электронная подпись (ЭП) на заявках. |
| Temporal        | Отказ от согласования в workflow.                                     | Средняя    | Среднее | Неотрекаемые уведомления (email/SMS с подтверждением), хранение истории в PostgreSQL ≥365 дней. |
| midPoint        | Отказ от provisioning (например, "я не назначал роль").               | Низкая     | Высокое | Центральный аудит всех операций, интеграция с SIEM для корреляции событий. |
| Общий           | Инсайдер отрицает несанкционированный доступ.                         | Средняя    | Высокое | MFA + биометрия для привилегированных ролей, ежеквартальная ресертификация. |

### 3.4. Information Disclosure (Раскрытие информации)  
Угрозы утечки конфиденциальных данных.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| PostgreSQL      | Утечка справочника сотрудников (data breach).                          | Средняя    | Высокое | Шифрование в покое, доступ по ролям (RBAC), DLP-мониторинг. |
| Traefik         | Прослушка трафика (MITM).                                             | Низкая     | Высокое | TLS 1.3 everywhere, HSTS, certificate pinning. |
| React Portal    | Утечка через API (например, overfetching данных).                     | Средняя    | Высокое | GraphQL с ограничениями, token scopes, аудит запросов. |
| Целевые системы | Утечка credentials в коннекторах.                                     | Средняя    | Высокое | Vault для хранения секретов, ротация ключей, минимальные привилегии. |

### 3.5. Denial of Service (Отказ в обслуживании)  
Угрозы, приводящие к недоступности.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| Traefik         | DDoS на ingress.                                                      | Высокая    | Высокое | Rate limiting, WAF, autoscaling в Kubernetes. |
| Temporal        | Перегрузка workflow (массовые заявки).                                | Средняя    | Среднее | Quotas на API, circuit breakers. |
| midPoint        | DoS на provisioning (например, loop в коннекторах).                   | Низкая     | Высокое | Resource limits в Docker, мониторинг (Prometheus). |
| PostgreSQL      | Query flood (замедление БД).                                          | Средняя    | Высокое | Indexes, query optimization, connection pooling. |

### 3.6. Elevation of Privilege (Повышение привилегий)  
Угрозы несанкционированного доступа к повышенным правам.  

| Компонент       | Угроза                                                                 | Вероятность | Влияние | Митингация |
|-----------------|------------------------------------------------------------------------|-------------|---------|------------|
| Authentik       | Escalation через уязвимость в MFA.                                    | Низкая     | Высокое | Least privilege, регулярные обновления, penetration testing. |
| midPoint        | Получение admin-ролей через SoD-байпас.                               | Средняя    | Высокое | Автоматическая проверка SoD (>10 конфликтов), birthright-роли только на основе HR. |
| Temporal        | Escalation в workflow (подмена согласующего).                         | Средняя    | Высокое | Delegation с аудитом, эскалация только по иерархии. |
| Общий           | Инсайдер эскалирует через legacy-интеграцию.                          | Высокая    | Высокое | Zero-trust, MFA для админов, ежеквартальный аудит доступов. |

## 4. Общая оценка рисков  
- Высокие риски: Spoofing и Elevation (из-за человеческого фактора).  
- Средние: Tampering и Disclosure (защищены криптографией).  
- Низкие: Repudiation (сильный аудит).  
Общий уровень: Средний, при условии реализации митингаций.  

## 5. Рекомендации по минимизации  
- Регулярное тестирование: Penetration testing (OWASP ZAP), нагрузочное.  
- Мониторинг: SIEM для логов, alerting на аномалии.  
- Обновления: Автоматический CI/CD с GitHub Actions/Terraform.  
- Соответствие: Аудит на GDPR/ФЗ-152 ежеквартально.

## Риск 1: DDoS на Traefik (2,8)
Сценарий угрозы
Злоумышленник (внешний или инсайдер) инициирует распределённую атаку на ingress-контроллер Traefik, используя ботнеты для генерации L7-запросов (например, HTTP flood на /api или self-service портал). Это может привести к исчерпанию ресурсов (CPU/RAM) в Kubernetes, особенно если не настроены лимиты. Воспроизводимость высока, так как Traefik экспонирован внешне, а эксплуатация проста с использованием инструментов вроде LOIC или cloud-based DDoS-сервисов. Обнаруживается по метрикам (Prometheus), но без WAF может быть поздно.
Потенциальные последствия

Недоступность self-service портала (>1000 пользователей не смогут подавать заявки на доступы).
Задержки в workflow (Temporal) и provisioning (midPoint), приводящие к срыву SLA (≤24 ч для birthright).
Финансовые потери: downtime в критических системах (SAP/1C), репутационные риски по ФЗ-152.
Масштаб: все 1000+ пользователей + 27 целевых систем.

Расширенные стратегии минимизации

Использование защиты облачного провайдера: Внедрить встроенные DDoS-митингации от AWS/GCP/Azure, такие как AWS Shield или Google Cloud Armor, для поглощения трафика на L3/L4. Это снижает нагрузку на Traefik.
Rate-limiting на ingress: Настроить аннотации Traefik для ограничения запросов (например, 100 req/min на IP), комбинируя с connection limits для предотвращения простых DDoS.
WAF и GeoIP-фильтрация: Интегрировать ModSecurity или Traefik Middleware для блокировки подозрительного трафика; добавить GeoIP для ограничения доступа только из РФ/корпоративных сетей.
Autoscaling и circuit breakers: В Kubernetes настроить HPA (Horizontal Pod Autoscaler) для Traefik и backend-сервисов; использовать Istio/Envoy для circuit breaking.
Мониторинг: Интегрировать с ELK/Prometheus для алертов на аномалии (спайки трафика).

DREAD пересчёт после митингаций: 2,0 (Средний).

## Риск 2: XSS/CSRF в React Portal (2,6)
Сценарий угрозы
Злоумышленник внедряет вредоносный скрипт через уязвимости в React (например, dynamic rendering пользовательского ввода в заявках) или CSRF-токены, подменяя действия (создание/отзыв доступов). Воспроизводимо при эксплуатации известных уязвимостей (OWASP Top 10), лёгкость высока для веб-атак. Затрагивает всех пользователей портала; обнаруживается по логам, но постфактум.
Потенциальные последствия

Несанкционированное назначение/отзыв ролей, нарушение SoD.
Утечка данных (справочник сотрудников), компрометация compliance (GDPR/ФЗ-152).
Репутационные потери, штрафы; влияние на 1000+ пользователей.

Расширенные стратегии минимизации

OWASP XSS Prevention: Использовать output encoding (React's dangerouslySetInnerHTML с санитизацией via DOMPurify) и framework protections.
CSRF Protection: Внедрить Synchronizer Token Pattern (генерация уникальных токенов на сервере, проверка в заголовках); избегать secret cookies, только POST для мутаций.
CSP и SRI: Настроить Content Security Policy (CSP) strict-dynamic, Subresource Integrity для скриптов; X-Frame-Options: DENY.
Автоматическое тестирование: Интегрировать OWASP ZAP/Nuclei в CI/CD для сканирования уязвимостей на каждом коммите.
Мониторинг: Логировать все запросы с OWASP ModSecurity rules.

DREAD пересчёт: 1,8 (Средний).

## Риск 3: Компрометация Authentik (2,4)
Сценарий угрозы
Атака на Authentik через MFA fatigue (бомбардировка пуш-уведомлениями) или кражу токенов (session replay). Воспроизводимо через социальную инженерию; лёгкость средняя с инструментами вроде Evilginx. Затрагивает всех; обнаруживается по алертам.
Потенциальные последствия

Полный доступ к порталам, манипуляция ролями, утечка PII (ФЗ-152 нарушения).
Каскадный эффект на 27 систем; юридические риски.

Расширенные стратегии минимизации

Адаптивный MFA: Внедрить risk-based authentication (RBA): повышать уровень MFA по риску (гео, устройство), снижая частоту промптов.
FIDO2/Passwordless: Перейти на аппаратные ключи (YubiKey) для админов, минимизируя fatigue.
Ограничение попыток: Блокировка после 10 неудач, уведомления о подозрительных входах.
Мониторинг токенов: Отслеживать token theft через поведенческий анализ (аномальные IP).

DREAD пересчёт: 1,8 (Средний).

## Риск 4: Компрометация midPoint admin (2,4)
Сценарий угрозы
Фишинг или слабые пароли приводят к захвату admin-учётки midPoint, позволяя создавать/изменять роли. Воспроизводимо; лёгкость средняя. Затрагивает всю систему.
Потенциальные последствия

Нарушение RBAC/SoD, несанкционированный доступ к 27 системам.
Compliance-штрафы (SOX/GDPR).

Расширенные стратегии минимизации

PIM/PAM: Внедрить Privileged Identity Management: временный доступ, just-in-time elevation.
MFA и Password Policy: Строгие политики (min 16 символов, ротация), MFA всегда.
Сегрегация: Отдельные учётки для серверов/воркстейшн, ограничение сетевого доступа.
Автоматизация: Workflow для изменений, аудит.

DREAD пересчёт: 1,8 (Средний).

## Риск 5: Утечка секретов в коннекторах (2,4)
Сценарий угрозы
Утечка credentials (API-ключи для 1C/SAP) через misconfig в Kubernetes secrets или logs. Воспроизводимо при скане репозиториев; лёгкость средняя.
Потенциальные последствия

Доступ к целевым системам, data breach.
Каскадные утечки PII.

Расширенные стратегии минимизации

Централизованное управление: Использовать HashiCorp Vault для динамических секретов, инъекция в pods.
Encryption at Rest: Включить K8s EncryptionConfig для secrets.
Vault Secrets Operator: Определение секретов в Git без значений, автоматическая ротация.
Сканирование: Trivy/Snyk в CI/CD для выявления утечек.

DREAD пересчёт: 1,8 (Средний).

## Риск 6: Инсайдер-backdoor в RBAC (2,4)
Сценарий угрозы
Инсайдер (admin) создаёт скрытую роль с elevated privileges, байпасс SoD. Воспроизводимо; обнаружение трудно без аудита.
Потенциальные последствия

Долгосрочный несанкционированный доступ, утечки.
Нарушение compliance.

Расширенные стратегии минимизации

Детекция: Мониторинг аномалий (UEBA), аудит изменений ролей.
Профилактика: Двойное одобрение изменений, least privilege.
IDS для инсайдеров: Блокировка неавторизованных доступов.

DREAD пересчёт: 1,8 (Средний).

## Заключение
Расширенный анализ снижает общий уровень рисков до Среднего. Рекомендуется внедрение в 2026 г.
