## 3. Основные понятия и определения

### 3.1. Термины и определения
- **Система**: Централизованная платформа для управления правами доступа и учетными записями.  
- **Доступ**: Право на использование ресурсов или выполнение операций.  
- **Роль**: Набор прав и обязанностей, назначаемый пользователям.  
- **Заявка**: Запрос на изменение доступа, роли или других параметров.  
- **Ресертификация**: Периодическая проверка и подтверждение прав доступа.  
- **Аудит**: Мониторинг и анализ событий для обеспечения соответствия.  

### 3.2. Обозначения и сокращения

| Сокращение | Расшифровка |
|------------|-------------|
| СУПД       | Система управления правами доступа и учетными записями |
| УЗ         | Учетная запись |
| БП         | Бизнес-процесс |
| ПКЗИ       | Программно-криптографическое средство защиты информации |
| СЗИ        | Средство защиты информации |
| ИБ         | Информационная безопасность |
| ОС         | Операционная система |
| СУБД       | Система управления базами данных |

## 4. Общие сведения о системе

### 4.1. Полное наименование системы и ее условное обозначение
Полное наименование: Система управления правами доступа и учетными записями пользователей в корпоративных информационных системах.  
Условное обозначение: СУПД.  
Регистрационный номер: 000.205.000.000.

### 4.2. Назначение системы
Система предназначена для систематизации и автоматизации процессов предоставления доступа, управления учетными записями и ролями в рамках бизнес-процессов верхнего уровня, включая управление данными о работниках, информационными ресурсами, ролями и правами доступа, временными организационными структурами, аудитом, предприятиями и системами.  
Система обеспечивает: управление данными о работниках и правах, ролями и ресурсами, заявками, ручной ввод данных, формирование отчетов аудита и хранимых данных.

### 4.3. Режимы функционирования системы и связанные с ними действия администратора

| Режим | Описание | Действия администратора |
|-------|----------|-------------------------|
| Нормальный | Обычная эксплуатация | Мониторинг, обслуживание |
| Тестирование | Проверка функционала | Настройка тестовых сред |
| Восстановление | После сбоя | Восстановление из резервных копий |
| Аудит | Проверка событий | Анализ логов |

Подсистема защиты информации включает режимы: нормальный, ограниченный доступ, аудит.

## 5. Общие сведения об администрировании системы
Администрирование включает управление пользователями, ролями, заявками, безопасностью и резервным копированием. Администратор обеспечивает соответствие требованиям безопасности и непрерывность работы.

## 6. Описание операций в пользовательском интерфейсе

### 6.1. Описание пользовательского интерфейса системы
Интерфейс включает: логотип, главное меню (боковая панель), меню быстрого доступа (запросы доступов, отзыв, просмотр), разделы отправленных и входящих заявок, кнопки переходов.  
Главное меню: Заявки, Управление, Администрирование, Отчеты, О системе.

### 6.2. Просмотр списка пользователей
Войдите под учетной записью администратора.  
Выберите "Управление > Пользователи". Откроется список. Фильтруйте по подразделениям или должностям.

### 6.3. Просмотр карточек пользователей
В списке пользователей нажмите на ФИО. Откроется карточка с вкладками: информация, трудоустройства, доступы, учетные записи, делегаты, делегирования, история.

### 6.4. Редактирование данных пользователей
В карточке нажмите "Редактировать". Измените данные (телефон, дата окончания работы). Сохраните. Для трудоустройств перейдите на вкладку, добавьте или измените.

### 6.5. Просмотр истории изменения доступов пользователя
В карточке перейдите на вкладку "История изменения доступов". Отобразится перечень событий.

### 6.6. Создание роли и настройка полномочий
Выберите "Управление > Роли". Нажмите "Добавить роль". Заполните атрибуты, сохраните. Для включения других ролей отредактируйте состав. Авторизации настраиваются в административном интерфейсе через XML.

### 6.7. Просмотр и редактирование ролей и их карточек
В списке ролей выберите роль. Откроется карточка. Нажмите "Редактировать", внесите изменения. Добавьте роли в состав на вкладке.

### 6.8. Просмотр заявок
Выберите "Заявки > Входящие" или "Отправленные". Просмотрите вкладки: ожидающие, делегированные, обработанные, активные, завершенные. Для деталей нажмите на номер.

### 6.9. Создание заявки
- На назначение роли: Выберите "Запросить доступы", укажите пользователя, доступы, период, комментарий.  
- На изменение срока: В карточке выберите "Изменить срок", укажите новый период.  
- На ресертификацию: В доступах выберите "Пересмотреть".  
- На отзыв: Выберите "Отозвать доступы", укажите пользователя и доступы.  

### 6.10. Просмотр истории по заявкам
Выберите "Заявки > Отправленные > Завершенные" или "Все". Фильтруйте по типу, инициатору и т.д.

## 7. Настройка параметров безопасности

### 7.1. Настройка параметров безопасности виртуальной инфраструктуры
Настройте журналирование: укажите серверы syslog.  
Парольная политика: максимальный срок, повторяемость, длина, символы.  
Доступ к консоли: таймауты.

### 7.2. Настройка параметров безопасности операционной системы
- Журналирование: настройте rsyslog, ротацию.  
- Парольная политика: хэширование, классы символов, блокировка.  
- Доступ к консоли: интервалы.  
- Контроль целостности: скрипты для сумм, расписание.  
- Аудит: правила в audit.rules, ротация, отправка в систему мониторинга.

### 7.3. Настройка параметров безопасности сервера баз данных
Настройте трассировку для INSERT, UPDATE, DELETE. Проверьте запуск при старте.

### 7.4. Порядок обновления программного обеспечения
Устанавливайте обновления безопасности timely. Тестируйте перед применением.

- Внеплановые: Инициируйте при изменениях, вирусах, обновлениях.
