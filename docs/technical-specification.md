# Техническое задание
на разработку системы «СУПД — Система управления правами доступа и учётными записями»
(Identity Governance & Administration, IGA/IDM)

Версия 1.1 от 05 декабря 2025 г.

## 1. Общие положения
| Параметр | Значение |
|----------------------------------|--------------------------------------------------------------------------|
| Полное наименование | Система управления правами доступа и учётными записями пользователей в корпоративных информационных системах |
| Краткое наименование / код | СУПД |
| Регистрационный номер в ИТ-учёте | 000.205.000.000 |
| Заказчик | Департамент информационной безопасности |
| Количество пользователей | > 1 000 активных сотрудников + подрядчики (ожидаемый рост до 1 500 в течение года) |
| Количество управляемых ИС | 27 (глобальные и локальные РФ, с возможностью расширения до 35) |
| Срок реализации | 6 месяцев с момента утверждения ТЗ (с возможностью корректировки на основе этапа анализа) |
| Бюджет на лицензии | 0 ₽ (только open-source компоненты, без проприетарного ПО) |

**Примечание:** В случае необходимости использования дополнительных open-source инструментов, они должны быть предварительно согласованы с Заказчиком.

## 2. Цели и задачи проекта
| № | Цель / задача | Целевой показатель | Метрика измерения |
|---|-----------------------------------------------------------------------------------------------|----------------------------------------|-------------------|
| 1 | Обеспечить новых сотрудников базовым набором доступов в течение 1 рабочего дня | ≤ 24 ч | Время от приема на работу до активации birthright-ролей |
| 2 | Обеспечить действующих сотрудников дополнительными доступами | ≤ 48 ч | Время от подачи заявки до исполнения |
| 3 | Исключить несанкционированное и некорректное предоставление прав | 100 % автоматическая проверка SoD | Количество заблокированных заявок с конфликтами |
| 4 | Полностью уйти от бумажного документооборота по заявкам на доступ | 100 % электронный юридически значимый документооборот | Доля заявок, обработанных электронно |
| 5 | Создать единый актуальный справочник сотрудников, ролей и ресурсов | Один источник правды | Синхронизация данных без расхождений > 1 % |
| 6 | Обеспечить ежеквартальную ресертификацию доступов и автоматический отзыв просроченных | 100 % охват | Доля ресертифицированных доступов в кампании |

**Дополнительные задачи:**
- Минимизировать ручной труд администраторов (цель: автоматизация ≥ 80 % операций).
- Обеспечить интеграцию с существующими системами без нарушения их работы.

## 3. Область применения и масштабы
- **Пользователи:** 1 000+ активных сотрудников, включая подрядчиков и временных работников.
- **Организационная структура:** 16 департаментов, 11 локаций (Москва, Самара, Краснодар, Новороссийск и др.), с поддержкой иерархии.
- **Роли:** 83 бизнес-роли (с возможностью добавления новых без перезапуска системы).
- **Целевые системы:** 27 информационных систем, включая SAP S/4HANA, 1С:ERP, Microsoft 365, ServiceNow, ФГИС Зерно и др. (приоритет на ключевые: 5 систем в первой фазе).
- **Ограничения:** Система не предназначена для управления физическим доступом (например, пропусками в здания). Фокус на цифровых аккаунтах и правах.

## 4. Функциональные требования (по подсистемам)
### 4.1. Self-service портал и интерфейсы
| Требование | Обязательно | Детали |
|-------------------------------------------|-------------|--------|
| Три типа интерфейса: Открытый (для гостей), Защищённый (с ПКЗИ для чувствительных данных), Мобильный (только согласование) | Да | Поддержка двухфакторной аутентификации (MFA) для защищённого. |
| Адаптивный дизайн (desktop + mobile PWA) | Да | Progressive Web App для оффлайн-доступа к базовым функциям. |
| Поддержка браузеров: Safari iOS, Firefox Android, Chrome, Edge | Да | Тестирование на актуальных версиях (не старше 1 года). |
| Первичное подтверждение ознакомления с ЛНД (локальными нормативными документами) | Да | Электронная подпись или чекбокс с логгированием. |

### 4.2. Управление пользователями и оргструктурой
| Функция | Обязательно | Детали |
|----------------------------------------------------------------|-------------|--------|
| Импорт и ежедневная синхронизация из 1С:ЗУП (CSV / REST) | Да | Автоматический импорт по расписанию (cron), обработка дельты изменений. |
| Полная карточка сотрудника (трудоустройства, доступы, история) | Да | Поиск по ФИО, табельному номеру; экспорт в PDF/CSV. |
| Поддержка иерархической оргструктуры (Управление → Отдел → Подразделение → Локация) | Да | Визуализация в виде дерева; поддержка перемещений с автоматическим обновлением ролей. |
| Автоматическое назначение birthright-ролей при приёме/перемещении | Да | На основе должности и локации. |
| Автоматический отзыв всех доступов при увольнении | Да | С уведомлением администратора и логгированием. |

### 4.3. Управление ролями и матрица доступа (RBAC + SoD)
| Функция | Обязательно | Детали |
|----------------------------------------------------------------|-------------|--------|
| Поддержка 83 ролей и матрицы доступа к 27 ИС (уровни: Admin / Read-Write / Read / No) | Да | Матрица в формате редактируемой таблицы (UI). |
| Автоматическая проверка SoD при подаче заявки (реестр ≥ 10 конфликтов) | Да | Блокировка заявки с объяснением конфликта; возможность исключений с одобрением ИБ. |
| Возможность создания составных ролей и связанных полномочий | Да | Иерархия ролей (родительские/дочерние). |
| Назначение ролей на должность / подразделение (birthright) | Да | Массовое назначение для групп. |

| Этап workflow | Обязательно | Детали |

| Этап | Срок | Результат | Зависимости |

**Итого: 26 недель (≈ 6 месяцев).** Риски задержек: интеграции с legacy-системами (митigation: пилот на 2 ИС).

## 8. Критерии приёмки проекта
1. Система запускается командой `docker compose up -d` на чистой машине за ≤ 15 минут (тест на Ubuntu 22.04+).
2. Полностью реализован workflow с 5 согласующими и автоматической проверкой SoD (тест на 10 сценариях).
3. Импортированы 500 тестовых пользователей из предоставленного Excel (без ошибок > 1 %).
4. Работает ежеквартальная ресертификация (симуляция кампании с 100 пользователями).
5. Сгенерированы и утверждены все три вида отчётов (проверка на compliance).
6. Прошёл penetration test (OWASP ZAP + manual) без критических уязвимостей (CVSS ≥ 7.0).
7. Передана вся документация (в Markdown/PDF), исходный код в GitHub (с CI/CD пайплайнами), и проведено обучение (2 сессии по 4 ч).

**Дополнительные критерии:** SLA на этапе UAT ≥ 99 %; покрытие кода тестами ≥ 80 %.
